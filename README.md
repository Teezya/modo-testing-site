# MODO — учебная платформа (обновление истории МОДО)

## Что изменено
- При старте сервер проверяет тему и задание исходного теста МОДО.
- После подключения к MongoDB автоматически импортируется последняя завершённая попытка старого теста для каждого ученика в новую систему `Submission`.
- В импортированной работе сохраняются ответы, дата завершения, балл и исходные значения балла/максимума.
- Импорт идемпотентный: у каждой новой записи есть ссылка `legacyAttempt`; повторный запуск не создаёт повторную запись.
- Исходные документы коллекции `Attempts` не изменяются и не удаляются.
- Новые результаты становятся доступны карточке темы, таблице класса и отчёту по теме через существующие API.

## Перед запуском
1. Сделайте резервную копию MongoDB (Atlas → Database → Backup / либо экспорт коллекций `Students`, `Attempts`, `Topics`, `Assignments`, `Submissions`).
2. Используйте прежний `MONGODB_URI`, чтобы видеть старые данные. Не публикуйте `.env` и не добавляйте его в ZIP/Git.
3. Проверьте `server/.env`: `MONGODB_URI`, `JWT_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`.
4. В корне проекта выполните `npm run install:all`, затем `npm run dev`.
5. В логах сервера найдите строку `Legacy MODO history migration: ...` — она показывает число импортированных результатов.

## Важная логика импорта
- Переносится последняя завершённая попытка на каждого ученика, поскольку в старой системе один ученик мог проходить тест несколько раз.
- Незавершённые попытки не отображаются как сданные.
- Старые `Attempts` остаются в базе. Для повторного запуска используется связь `legacyAttempt`.
- Если в MongoDB нет завершённых попыток, импортировать нечего; проверьте, что приложение подключено именно к прежней базе и коллекции.

## Безопасность
Автоматическая миграция создаёт только документы в новой коллекции `Submissions` и не удаляет старые данные. Всё равно сначала сделайте резервную копию рабочей базы и проверьте результат на копии, если это возможно.
